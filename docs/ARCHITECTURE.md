# Архитектура StroyControl

Соответствует разделу 16 ТЗ.

## Стек технологий

| Слой | Технология | Обоснование |
|---|---|---|
| Backend | Node.js + TypeScript, Express | быстрая разработка REST API, единый язык с web/mobile |
| БД | PostgreSQL | реляционная модель хорошо ложится на иерархию объектов, есть JSONB для гибких полей |
| ORM | Prisma | типобезопасный доступ к БД, миграции из коробки |
| Web | React + TypeScript + Vite | быстрый билд, широкая экосистема |
| Mobile | React Native (Expo) | единый код iOS/Android на TS, переиспользование логики с web |
| Медиа-хранилище | S3-совместимое объектное хранилище + CDN | масштабируемое хранение фото/видео/документов |
| Реальное время | WebSocket (Socket.IO) | лента, уведомления, live-обновления графика |
| Видео | RTSP → HLS медиасервер (например, MediaMTX) | подключение IP-камер (RTSP/ONVIF), архив |
| Очереди/фон. задачи | BullMQ + Redis | обработка фото (AI-анализ, таймлапсы), эскалации SLA |
| AI-слой (Этап 3) | локальные модели распознавания + векторный поиск по документам | анализ фото, Q&A по документам |

## Многоуровневая мультитенантность

Каждая запись домена привязана к `company_id`. Изоляция обеспечивается на уровне
приложения (обязательный `company_id` в каждом запросе) и опционально усиливается
Row-Level Security в PostgreSQL.

## Иерархия домена

```
Company → Object → Stage → WorkSection → Task → Subtask
```

См. [DATABASE_SCHEMA.sql](DATABASE_SCHEMA.sql).

## Модульная структура backend

```
backend/src/
├── modules/
│   ├── objects/        # объекты, этапы, разделы, график, Гант
│   ├── tasks/           # задачи, чек-листы, SLA
│   ├── photocontrol/     # фотоконтроль, дефект-лист, акты
│   ├── feed/             # лента, коммуникации
│   ├── documents/         # документооборот, версии, согласования
│   ├── customer-portal/    # кабинет заказчика
│   ├── finance/            # Этап 2: бюджет, план/факт
│   ├── supply/              # Этап 2: снабжение, склад, инструмент
│   ├── video/                # Этап 2: видеонаблюдение
│   └── ai/                    # Этап 3: AI-функции
├── auth/                # аутентификация, RBAC-мидлвары
├── shared/               # общие утилиты, типы
└── index.ts
```

## Открытые архитектурные решения (требуют согласования с заказчиком)

- Облачный провайдер (стоимость, соответствие 99.9% SLA, наличие в регионе РУз/СНГ)
- Провайдер S3-совместимого хранилища и CDN
- Способ подключения электронной подписи (Этап 2)
- Провайдер распознавания речи RU/UZ для голосового журнала (Этап 3)
